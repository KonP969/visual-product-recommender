Visual Product Recommender

You upload a photo of a room and get interior doors matched to it by colour and style.

Why similarity alone isn't enough

People pick doors by eye, but describe them in words: "something darker", "no glass", "loft style". The search has to handle both at once.

Vectors catch similarity and stop there. Ask for doors with no glass, you got glazed ones. Ask for black, you got dark brown. Rewording the prompt didn't help here, because a vector cannot account for (or rather, encode) either negation or a hard colour.

So at import time I compute three attributes for each product and store them alongside it: colour family, whether it has glass, and style. The search filters on those hard, inside the same query that computes similarity. The rest of the similarity can be pulled from the vector.

How it works

What happens in the "MMR + dedup" step

Without this stage the top ten is often ten near-identical doors. That happens for two different reasons, so there are two remedies.

Collapsing variants (dedup). The feed carries several entries under an identical name: the same model in the same colour, from different price lines. In a grid they look like repeats of one product. So I collapse them into a single card, showing the best-matching variant, the cheapest price ("from 1,051 zł") and how many variants wait in the configurator.

Diversification (MMR). Even with the repeats gone, similarity search likes to return ten variations on one idea, because they all sit close to the query. MMR (Maximal Marginal Relevance) picks ten out of a larger candidate pool, scoring each next one not only on how well it matches the query, but on how much it differs from the ones already chosen.

Where the model got it wrong most often

All four of these bugs passed the tests. They surfaced only when I sat down and looked at real results on a real feed.

Green doors classified as black

What the classifier decided

colour: black

What was actually true

sage green

The "Szałwia" (sage) finish had no colour rule of its own, so classification fell back to the model's English description. There, the word black described a black glass insert, not the door leaf. Searching "black doors" returned green ones.

68 variants with the wrong colour

Black doors classified as white

What the classifier decided

colour: white

What was actually true

a black frame

A line of plain glass panels names the variant after the glass type, for example "matte pane". The description read white frosted, which referred to the opacity of the glass, not the frame. The frame on every one of those SKUs is black.

11 SKUs · searching "white doors" returned black ones

Entrance doors passing as interior ones

What the classifier decided

type guessed from the name

What was actually true

type is stated in the feed

The code guessed the door type from the product name, even though the feed states it outright in a separate field. Anything unrecognised defaulted to "interior", along with technical, sliding and apartment entrance doors.

1,919 variants across 88 models · catalogue 10,873 → 6,360

The variant counter counted the wrong set

What the classifier decided

variants in the search pool

What was actually true

variants in the whole catalogue

The product card showed how many variants appeared in that one search, so it almost never matched the manufacturer's configurator. The customer saw a number they had no way to verify.

a true number answering the wrong question

Which is what real human-in-the-loop work looks like: tests check that the code does what you wrote. They don't check whether you wrote the right thing. All four bugs passed 259 green tests and surfaced only when someone looked at actual doors.

And what couldn't be done?

Style recognition that matches reality.

Take Scandinavian. One door model comes in a dozen or so colours, and style is assigned to the whole model, not to an individual colour. For most styles that works: a loft door is a loft door whether it's black or oak.

Scandinavian doesn't behave that way, because colour is exactly the point. Pale wood. The same model in dark oak isn't Scandinavian any more. And since nearly every model ships in both pale and dark finishes, none of them collects enough votes from the model to earn the label.
